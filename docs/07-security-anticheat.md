# 07 · 安全与反作弊（Security & Anti-Cheat）

## 1. 威胁模型
浏览器是**完全可被检视、可被篡改**的敌对环境。攻击者可以：
- 修改客户端内存/JS，伪造任意分数、击杀数、通关事件。
- 重放抓取到的网络请求，重复领取奖励。
- 直接调用链上程序，试图绕过游戏写入分数/铸币。
- 用脚本机器人刷量。

**铁律**：**客户端永不直接铸币、永不写未经服务端校验的分数上链。**
服务端是"你是否真的赚到了这个"的唯一可信来源。

## 2. 奖励/上分流程（带校验）
```
1. 开局   GET /session-nonce  → 服务端签发：绑定钱包、限时、一次性 nonce
2. 游玩   累积分数；可记录紧凑输入/事件重放日志（确定性内核支撑）
3. 通关   POST /score {wallet, nonce, score, kills, durationMs, replayLog/hash}
4. 校验（由便宜到强）：
     a) 边界检查：每关最高分/击杀上限、最短合理时长、事件序列单调
     b) 会话 nonce：限时、绑定钱包、一次性 → 防重放/预制提交
     c) 服务端无头重放：用确定性内核重新模拟、重算分数（最强，工作量大）
     d) 限流 + 异常检测：按钱包/IP 频率与统计离群标记
5. 通过后：服务端（持 authority）签名提交链上排行榜 / 铸发代币
```

## 3. 关键控制点
- **密钥托管**：mint / leaderboard / result authority 私钥**只在后端**；生产用 KMS /
  硬件支持的密钥，不用明文 `.env`。任何 ship 到客户端的东西都视为公开。
- **幂等**：每次奖励/上分以 `nonce` 为键，重放请求无法二次领取（链上 `ClaimReceipt[nonce]` 兜底）。
- **链上 authority 门控**：程序 `require!` 调用者为已知 authority（server-submit），
  或验证 Ed25519 authority 签名（server-attest），任何人都无法直接调程序刷分/铸币。
- **产出上限**：每钱包/每时间窗的代币产出在程序/treasury 层封顶，即使校验器有 bug 也无法瞬间掏空。
- **钱包签名 = 身份，不 = 数据可信**：签名只证明"谁提交"，合法性由校验器负责。
- **确定性内核**：游戏用固定步长 + 种子 RNG，使无头重放可行、测试可复现。

## 4. 上线前安全清单
- [ ] 价值程序（reward-distributor、pvp-betting）**专业审计**通过。
- [ ] devnet 长期运行、压测、红队尝试作弊后再考虑主网。
- [ ] authority 私钥进 KMS；轮换与撤销预案。
- [ ] RPC 用付费提供商（Helius/Triton/QuickNode），写操作走后端、不在客户端硬编码。
- [ ] 速率限制 + 监控告警（异常领取/上分）。

## 5. 合规与法律（非技术但最高风险）
- **IP**：原创美术与命名，不碰《黑神话：悟空》资产；保留资产授权台账（见 `05`）。
- **P2E + 下注**：代币具真实价值、PVP 下注尤其敏感，可能触发**赌博 / 证券 /
  资金转移**等监管。主网/赋真实价值前**必须法律审查**，考虑地域限制、KYC 需求、
  "无需购买即可参与"框架，避免收益承诺式宣传。
- 这是整个项目**最大的非技术风险**，务必在 Phase 4/5 推进真实价值前处理。
